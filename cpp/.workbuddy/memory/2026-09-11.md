# 2026-09-11

## ByteTrack 参数化改造（对接 bytetrack_shaky.yaml）

- 原 `BYTETracker` 构造只有 `(frame_rate, track_buffer)`，`track_thresh_=0.6 / high_thresh_=0.3 / match_thresh_=0.9` 全部硬编码；且成员名 `high_thresh_` 实际对应 yaml 的 `new_track_thresh`（命名陷阱，原值 0.3 比分流线 0.6 还低，抖动场景会大量误开新 ID）。
- 改造内容：
  - `bytetrack/include/BYTETracker.h`：新增 `BYTETrackerParams` 结构体（frame_rate/track_buffer/track_high_thresh/track_low_thresh/new_track_thresh/match_thresh/fuse_score/min_box_area，默认值=ByteTrack 官方默认），新增 `BYTETracker(const BYTETrackerParams&)`，保留旧 2 参构造（委托实现）；成员重命名 `track_thresh_`→`track_high_thresh_`、`high_thresh_`→`new_track_thresh_`，新增 track_low_thresh_/fuse_score_/min_box_area_。
  - `bytetrack/src/BYTETracker.cpp`：update() 中新增 track_low_thresh 过滤（低分检测直接丢弃）与 min_box_area 过滤；新轨迹门槛改用 new_track_thresh_；构造时打印全部参数。
  - `bytetrack/src/utils.cpp`：两个 `iouDistance` 重载实现 fuse_score（相似度 = IoU × 检测分数）。
  - `utils/include/config_manager.h`：新增 `bytetrack:` 节 7 个 getter（getTrackerTrackBuffer/getTrackHighThresh/getTrackLowThresh/getNewTrackThresh/getMatchThresh/isFuseScoreEnabled/getTrackerMinBoxArea），默认值=官方默认；注意与既有 danger_alert 的 getMinObjectArea 区分，跟踪器的叫 getTrackerMinBoxArea。
  - `core/src/pipeline.cpp`：匿名命名空间新增 `makeTrackerParams(config_manager)`（frame_rate 取 camera.fps），构造初始化列表 `tracker_(makeTrackerParams(config_manager))`。
- 配置文件不在本仓库（运行时以命令行参数传入），用户需在自己的 config yaml 里加 `bytetrack:` 节；抖动场景推荐值 = bytetrack_shaky.yaml：high 0.30 / low 0.05 / new 0.60 / buffer 120 / match 0.90 / fuse_score true / min_box_area 100。
- 第二级关联 IoU 阈值 0.5、未确认轨迹匹配 0.7 仍硬编码（与官方参考实现一致）。
- 追加（同日）：应用户要求移除 `fuse_score` 和 `min_box_area` 两个参数——不再进 `BYTETrackerParams`/ConfigManager/配置节，iouDistance 恢复纯 IoU 代价，update() 移除框面积过滤。最终暴露的跟踪参数只有 6 个：frame_rate（取 camera.fps）、track_buffer、track_high_thresh、track_low_thresh、new_track_thresh、match_thresh。
- 追加（同日）：快速靠近（approach）尺度判据由"框面积变化"改为"框高变化"：`thr_area`→`thr_height`（默认 0.30，config key 同步改名）、检测器/滤波器内部 area 信号全部改为 height（框高），pipeline 传 `unit->h` 而非 `unit->area()`；`scale_score`/`approach_scale_score` 名称保留。**注意：bin/config.yaml 不在本仓库，需用户自行把 approach 段的 `thr_area` 改名为 `thr_height` 并重调数值（原 0.35 面积增幅 ≈ 0.16 框高增幅，建议 0.15~0.25）。**
- 追加（同日）：修复 TCP 报警 JSON 缺 depth 字段的问题：`danger_alert_handler.h` 里 `AlertObjectData` 有 `depth` 成员且 `buildAlert` 填了 `track.distance_`，但 `NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE` 字段列表漏了 `depth`，序列化时被直接丢弃；已把 `depth` 加进宏列表。注意 `track.distance_` 仅在 metric 深度图生效，深度关闭时该值为 0。同日追加：depth 发送时四舍五入到小数点后 2 位（`roundDepth2`，在 buildAlert 填充处截断，nlohmann 最短往返打印即输出 2 位小数）。
- 追加（同日）：画面上每个目标框都打印三项分数：`visual_manager.cpp` 的 drawTrackedObject 中分数行去掉 "APPROACH" 前缀，改为 `s=%.2f d=%.2f h=%.2f`（融合分/深度分/框高尺度分），且不再仅限报警目标绘制（未报警灰描边、报警红描边）；`main.cpp` 画框循环不再跳过无 motion_records 的目标（用默认 MotionStateInfoRecord，分数显示 0.00）。
- 追加（同日，用户四点需求）：① 接近单元装配 `assembleApproachUnits`：两轮车无论有无骑手都进接近单元（`require_rider` 规则停用，字段保留但注释标记已废弃）；② 有骑手且 merge_person 时仍合并为外接大框、unit_id 取两轮车 track id；③ 行人始终单独成单元（即使已被两轮车认领合并，也保留自己的判定单元，人被合并后自己也还有分数）；④ 分数改画在框内部左上角（白色小字+黑描边，`s= d= h=`），不再画在框上方；报警红框/红色填充逻辑不变。白名单外类别仍不参与判定（config 里 alarm_class_ids 可置空表示不限类别）。
